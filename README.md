# AI Dock Demo 2.0

独立任务工作区演示；原版目录、仓库与网址保持不变。

- 新站：https://kingangbian-prog.github.io/pc-ai-dock-demo-v2/
- 原站：https://kingangbian-prog.github.io/pc-ai-dock-demo/
- 基线：原版已发布 commit `5a4be2e3b7ec22a04800b0ec94391b30ef528e0d` 的本地项目副本。

全部任务、文档和 Computer Use 均为内置模拟数据。没有接入真实 Agent、真实应用、账号或私有文档。

## 运行

Node.js 20+，无需安装依赖：`npm start`，打开 http://127.0.0.1:4174/ 。`npm run check` 检查语法，`npm test` 运行测试。

## 2.0 体验

1. Goal 标题下显示参与此目标的 Agent 图标，悬停有完整名称。
2. 悬停或点击 Agent 图标展开按任务分组的卡片；Bot 下发的任务右上角显示 Bot 来源，直接指定 Agent 的手动任务不带该标记。
3. 千问的「评审简报初稿」可直接「查看输出文档」。文档在桌面独立窗口打开，仍归属原任务，不切换普通 Dock。再次打开同一输出聚焦原窗口；多个输出各自保留窗口与草稿。编辑保存在本机。
4. Agent 的任务卡聚合当前任务、已打开（包括最小化）的文档预览、Computer Use 实况。点击预览恢复对应窗口，点击任务标题查看进度详情。文档关闭后移除预览，重新打开仍保留草稿。
5. Workbuddy 的「竞品交互研究」包含 Computer Use。它与独立 Computer Dock 图标共用唯一 `cu-session-001`、同一控制者及上下文。接管和交还均等待 ACK，未保存编辑阻止交还。
6. 开始菜单打开 Office Word 等传统应用后，AI Dock 临时显示其运行图标。悬停或键盘聚焦展开窗口列表；可新建窗口，关闭最后一个窗口才移除图标。最小化仍算运行。不提供固定入口。
7. Dock 翻面、玻璃材质、任务多卡、实况补充输入和接管交还沿用原型实现。窄屏任务卡横向滚动。

## 数据隔离

2.0 使用 `ai-dock-prototype-v2`，不读写原版 `ai-dock-prototype-v1`。GitHub Pages 两站虽同域，也通过不同键隔离。草稿、任务、Goal、来源与 Computer 上下文持久化；打开窗口及其位置为当前页面状态，刷新不恢复窗口布局。刷新后从任务卡重新打开草稿。

关闭传统应用和文档窗口会结束该窗口实例；最小化只隐藏。Agent、Bot 和 Computer 的关闭仍只隐藏，不取消任务。

## 验证

43 项 Node 测试和 7 个运行模块语法检查通过。新增覆盖存储键隔离、Bot 来源传播、手动来源、多文档独立草稿及保持 AI 模式。原有测试覆盖任务交接、授权、失败重试、任务补充、翻面和接管交还。

实际浏览器验证桌面 1280×720、窄屏 390×844：Goal 参与图标、Bot 标记、任务文档打开/编辑/预览、重复打开、关闭最后窗口移除 Word、Computer 同一会话接管与交还。测试记录及截图位于 `screenshots-v2/`。未验证真实系统集成、其他浏览器或小于 390px 的屏幕。

静态站不含网络请求、遥测或第三方运行时依赖。

## 最新交互修订

Dock 图标始终单行，超宽时左右按钮或横向滚动访问全部入口。Bot 左侧 Goal 名称右侧显示实际调用 Agent：1–2 个并列，超过两个扇形堆叠。已打开的文档窗口改为独立预览卡并优先显示，Computer Use 也独立成卡；关闭文档同步移除该卡，任务进度卡保留。新增测试后总计 44 项通过，详见 QA.md。

## 最新生命周期规则（覆盖此前“任务卡保留”的说明）

关闭任务最后一个文档窗口后，Agent 预览同时移除该文档卡与相关任务进度卡；任务历史、输出版本和 Bot Goal 记录保留，不取消运行任务。该隐藏偏好会保存。最小化不移除；同任务仍有其他文档或 Computer Use 时保留入口。重新从 Goal/任务记录打开文档后恢复对应预览卡。当前测试共 47 项。
